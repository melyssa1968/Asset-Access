# Working instructions

- For every application code or configuration change, commit the complete change to GitHub first.
- Deploy to Vercel only from the GitHub-connected commit, and verify that the production deployment uses that commit.
- Do not make code-only changes directly in Vercel.
- Changes that must be made in a service dashboard—such as secrets, domains, or integrations—must be documented in the repository and verified against the deployed application.
- Before reporting completion, provide the GitHub commit and Vercel deployment status.
